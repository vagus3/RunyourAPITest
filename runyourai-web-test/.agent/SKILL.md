## [Phase 1: 자율 실행 및 생산성 극대화]

### 1. 단방향 비차단 실행 스킬 (Non-Blocking Execution Skill)
**목적:** 긴 빌드 시간, 서버 대기, 번들링 등 시간이 오래 걸리는 터미널 작업 시 에이전트가 블로킹(차단) 상태에 빠지지 않고 효율적으로 작업을 이어가도록 합니다.
**실행 규칙:**
- `npm run dev`, `cargo watch`, `docker-compose up` 등 지속형 프로세스를 실행할 때는 **백그라운드 비차단 방식**으로 시작한다.
- 명령 실행 후 출력을 기다리기 위해 대기 상태를 유지하지 말고, 다음 코드 편집이나 파일 생성 작업으로 즉시 전환한다.
- 필요한 경우 로그 파일(`/tmp/build.log` 등)로 출력을 리다이렉션하여 비동기로 상태를 확인한다.

### 2. 변경 계획 출력 스킬 (Change Plan Output Skill)
**목적:** 대규모 코드 변경 시 사용자가 에이전트의 변경 의도를 명확히 파악할 수 있도록 작업 착수 전 변경 구조와 영향을 한눈에 제시합니다.
**실행 규칙:**
- 코드를 직접 수정하거나 다수의 파일을 생성하기 전, **[변경 계획 (Change Plan)]** 요약을 터미널/대화창에 먼저 출력한다.
- 포함 요소:
  1. **수정/생성 대상 파일 목록**
  2. **핵심 변경 내용 및 아키텍처적 이유**
  3. **발생할 수 있는 사이드 이펙트 및 대비책**
- 계획 출력 후 사용자의 명시적 중단 요청이 없다면 지체 없이 구현에 착수한다.

### 3. 질문 없이 즉시 자율 코딩 스킬 (Autonomous Coding Skill)
**목적:** 사소한 구현 디테일(변수명, 폴더 구조, UI 미세 조정 등)로 인해 질문을 던져 사용자의 흐름을 끊지 않고 상식적 판단하에 끝까지 완수합니다.
**실행 규칙:**
- 명확한 모호함이나 환경적 오류가 없는 한 **"어떻게 할까요?"라는 중간 질문을 금지**한다.
- 기술 스택 표준 커벤션(Best Practice)에 맞춰 최선의 옵션을 스스로 판단(Opinionated Default)하여 바로 코드를 작성한다.
- 작성 완료 후 최종 결과 보고 시 스스로 결정한 판단 기준(Decision Log)을 짧게 요약 설명한다.

### 4. 터미널 자가 검증 스킬 (Terminal Self-Verification Skill)
**목적:** 작성한 코드가 실제로 빌드되고 린트(Linter) 오류나 타입 에러가 없는지 터미널 명령을 직접 실행해 스스로 검증합니다.
**실행 규칙:**
- 코드 작성/수정 완료 후 사용자에게 완료를 선언하기 전, **터미널 검증 명령어**를 직접 호출한다.
  - TypeScript/Next.js: `npx tsc --noEmit` 또는 `npm run build`
  - Linter: `npm run lint`
- 자가 검증 시 에러가 발생하면 사용자가 지적하기 전에 **스스로 오류 원인을 파악하고 수정(Auto-fix Loop)**을 거친 후 최종 완료한다.

## [Phase 2: 코드 안전성 및 환경 보호 (Safety Constraints)]

### 5. 최소 범위 변경 스킬 (Minimal Diff & Preservation)
**목적:** 코드 수정 시 기존 코드가 훼손되거나 무관한 주석 및 유틸리티가 삭제되는 현상을 방지합니다.
**실행 규칙:**
- 기존 코드를 전체 재작성하지 말고, 요청된 기능 수정에 필요한 **최소한의 영역(Line-level Diff)만 수정**한다.
- 수정 시 기존에 존재하는 주석, 가이드 문서, 연관 없는 유틸리티 함수를 임의로 삭제하지 않고 온전히 보존한다.

### 6. 패키지 추가 자제 및 기존 모듈 재활용 (Dependency Restraint)
**목적:** 무분별한 외부 라이브러리 설치로 인해 프로젝트가 무거워지거나 의존성이 꼬이는 것을 방지합니다.
**실행 규칙:**
- 신규 외부 패키지를 설치하기 전, 프로젝트 내부(`package.json`)에 **이미 설치된 라이브러리나 언어의 내장 유틸리티(Native API)로 해결할 수 있는지 먼저 확인**한다.
- 외부 패키지 추가가 불가피한 경우, [변경 계획] 단계에서 설치 이유와 패키지 용량 및 사이드 이펙트를 명시한다.

### 7. 보안 및 환경 변수 보호 (Security & Secret Shield)
**목적:** 민감한 보안 키와 인증 정보가 코드베이스나 버전 관리 시스템에 유출되는 것을 차단합니다.
**실행 규칙:**
- API 키, 데이터베이스 연결 URL, 비밀키 등의 민감한 정보는 **절대로 코드 내에 하드코딩하지 않는다.**
- 반드시 `.env.local` 또는 환경 변수 파일로 분리하여 참조(`process.env.XXX`)하도록 작성하며, `.gitignore`에 해당 파일이 포함되어 있는지 점검한다.

### 8. Git 안전망 및 백업 (Git Safety Checkpoint)
**목적:** 대규모 리팩토링이나 변경 작업 시, 문제가 발생했을 때 즉시 복구할 수 있는 복원 포인트를 확보합니다.
**실행 규칙:**
- 대규모 리팩토링이나 여러 파일에 걸친 구조 변경 작업을 시작하기 전, `git status`를 확인하고 필요시 작업 단위별로 가벼운 임시 커밋을 진행하거나 백업 브랜치를 생성한다.
- 자가 검증 실패나 로직 꼬임 발생 시, 억지로 수정하려다 망치지 말고 안전하게 원복(`git restore` 또는 임시 커밋 되돌리기)할 수 있는 지점을 항상 확보해 둔다.

### Git 커밋 규격

- Format: `<type>(<scope>): <short description>`
- Types: `feat` (기능), `fix` (버그), `style` (UI/Tailwind), `refactor` (리팩토링), `test` (테스트), `docs` (문서), `perf` (성능), `chore` (기타)
- Example: `feat(ai-key): 사용자 API 키 발급 컴포넌트 구현`
